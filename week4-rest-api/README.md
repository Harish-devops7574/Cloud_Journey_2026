# Users API: API Gateway + Lambda + DynamoDB (Terraform)

CRUD user-management REST API with `dev` and `prod` stages, built to match the Console/CLI version of Week 4, use case 1.

```
Client --x-api-key--> API Gateway (REST, regional)
                        |  stage variables: lambdaAlias, tableName
                        v
                  Lambda alias (dev -> $LATEST, prod -> pinned version)
                        |
                        v
                  DynamoDB (Users-dev-tf / Users-tf)
```

| Endpoint | Methods |
|---|---|
| `/users` | GET (list), POST (create), OPTIONS |
| `/users/{id}` | GET, PUT, DELETE, OPTIONS |

## Layout

| File | Purpose |
|---|---|
| [versions.tf](./versions.tf) | Terraform and provider versions, AWS provider config |
| [variables.tf](./variables.tf) | All inputs |
| [dynamodb.tf](./dynamodb.tf) | One table per stage |
| [lambda.tf](./lambda.tf) | Function, IAM role, aliases, invoke permissions |
| [api.tf](./api.tf) | API Gateway: resources, methods, CORS, deployment, stages, usage plan |
| [outputs.tf](./outputs.tf) | Invoke URLs and API key |
| [src/lambda_function.py](./src/lambda_function.py) | Lambda handler code |

## Prerequisites

- Terraform >= 1.5
- AWS credentials for an IAM user or role (not root) allowed to manage API Gateway, Lambda, DynamoDB, IAM roles and CloudWatch Logs
- Region `us-east-1` by default

## Usage

```bash
terraform init
terraform plan
terraform apply

KEY=$(terraform output -raw api_key_value)
DEV=$(terraform output -json invoke_urls | python3 -c "import sys,json;print(json.load(sys.stdin)['dev'])")
curl -s "$DEV" -H "x-api-key: $KEY"
```

Destroy: set `deletion_protection_enabled` to `false` for the prod table in `dynamodb.tf`, run `terraform apply`, then `terraform destroy`.

## versions.tf

Pins Terraform `>= 1.5` and the providers `hashicorp/aws ~> 5.0` and `hashicorp/archive ~> 2.4`. The AWS provider uses `var.region` and applies `default_tags` (`Project`, `ManagedBy`) to every taggable resource.

Commit `.terraform.lock.hcl` (generated by `init`) so everyone uses the same provider builds.

## variables.tf

| Variable | Default | Description |
|---|---|---|
| `region` | `us-east-1` | AWS region |
| `name` | `users-api-tf` | Base name; the `-tf` suffix avoids clashing with the console-built API |
| `allowed_origin` | `*` | CORS `Access-Control-Allow-Origin`. Restrict to your real domain in production |
| `stages` | `dev`, `prod` | Map of stage name to `table_name`, `lambda_alias`, `rate_limit`, `burst_limit`, `alias_to_latest` |
| `usage_plan` | 20 rps / 40 burst / 1000 per month | Usage plan throttle and quota |
| `log_retention_days` | `14` | Lambda log retention |

Adding a stage is one new entry in `stages`. Every `for_each` resource picks it up.

## dynamodb.tf

Creates one table per stage (`for_each = var.stages`).
- Key: `userId` (String), on-demand billing.
- Point-in-time recovery and server-side encryption enabled.
- `deletion_protection_enabled` is true for `prod` only.

## lambda.tf

- `archive_file` zips `src/lambda_function.py`; `source_code_hash` redeploys the function when the code changes.
- IAM role has `AWSLambdaBasicExecutionRole` plus an inline policy limited to GetItem, PutItem, UpdateItem, DeleteItem and Scan on the stage tables only.
- Log group `/aws/lambda/<name>` with retention.
- Function: Python 3.12, `publish = true` so each apply makes an immutable version.
- Aliases: `dev` tracks `$LATEST`; `prod` is pinned to the published version (`alias_to_latest = false`). Promote to prod by applying a new version.
- `aws_lambda_permission` per alias lets API Gateway invoke it. Permissions are per qualifier, so invoking an alias without its own permission returns 500.

## api.tf

- **REST API:** regional, with resources `/users` and `/users/{id}`.
- **CRUD methods:** `local.methods` drives the methods and integrations. Integration type is `AWS_PROXY`. The URI ends in `:${stageVariables.lambdaAlias}`, so one integration routes to the right alias per stage. All methods require an API key.
- **CORS:** `OPTIONS` methods use a MOCK integration and need no key. Gateway responses `DEFAULT_4XX` and `DEFAULT_5XX` also add CORS headers so 403/429 errors are readable by browsers.
- **Deployment:** Terraform does not redeploy when methods change, so a `triggers` hash of methods, integrations and CORS config forces a new deployment. `create_before_destroy` avoids downtime.
- **Stages:** one per entry in `stages`, with `lambdaAlias` and `tableName` stage variables.
- **Throttling:** `method_settings` on `*/*` per stage (rate and burst).
- **Usage plan:** `<name>-basic` covers all stages, with throttle and monthly quota, and one API key attached.

Throttling is best-effort, and the account's Lambda concurrency (about 10 on new accounts) is the practical limit under load.

## outputs.tf

| Output | Description |
|---|---|
| `invoke_urls` | Map of stage to `/users` URL |
| `api_key_id` | Key ID, for use with `aws apigateway get-api-key` |
| `api_key_value` | Key value (sensitive) |

## src/lambda_function.py

Python handler for API Gateway proxy events. The table name comes from the `tableName` stage variable. CORS headers are set on every response, and the allowed origin comes from the `ALLOWED_ORIGIN` environment variable.

| Request | Response |
|---|---|
| GET `/users` | 200, list (scan) |
| POST `/users` | 201, created user (generates `userId` if missing) |
| GET `/users/{id}` | 200, or 404 |
| PUT `/users/{id}` | 200, replaced item |
| DELETE `/users/{id}` | 204, empty body |
| bad JSON | 400 |
| other | 405 |

## Security notes

- Never commit state files: they contain the API key value in plain text. `.gitignore` excludes them. Use a remote backend (S3 with locking) for shared work.
- Use an IAM user or role, not root credentials.
- `allowed_origin = "*"` is for testing only.
- The API key is for throttling and identification, not authentication. Use Cognito or another authorizer for real auth (use case 2).
